# 对话内变更审阅

每轮会话下方汇总文件数及已知增删行数。未知行数不按零伪装完整统计。
点击文件行原地展开 diff，旁边的打开按钮可直接进入文件工作区。
展开后可刷新差异、打开内容、在文件工作区审查，以及安全撤销。

`dist`、`build`、`out`、`coverage` 等目录和压缩脚本、source map
按路径规则归入默认折叠的生成文件组；这是展示分组，不是文件删除或作者判断。
普通列表初次显示 60 项，可逐批继续；生成文件单独分页。
补丁只在展开时读取，关闭即卸载视图；虚拟行复用现有 FileLines，
不因文件长度增加 DOM 行数。预览达到后端大小上限时明确显示提示。

文件清单来自本轮基线与结束快照；现有 Git 行数及补丁接口比较的是
**当前工作区与 Git 基线**，并非不可变的历史逐轮补丁。
运行器和模型来自任务执行配置，不作为逐行作者证据。

## 撤销

执行中不可撤销。结束后先确认，再在后端同时取得会话和工作区预留：

1. 确认快照完整且文件属于本轮变更。
2. 用 SHA-256 检查当前内容等于结束快照；删除的文件必须仍未出现。
3. 确认起始文件等于起始时记录的 Git commit 内容。
4. 将待替换内容和恢复说明保存到应用数据目录 `turn-undo/<随机ID>/`。
5. 用固定 commit 恢复工作区，保留暂存区；本轮新增文件仅删除已核验的单个文件。

冲突不自动覆盖；显示原因并提供“查看当前差异”入口。
成功后提供“查看恢复备份”，其中 `content` 是撤销前的原始内容，
`restore.json` 记录原路径及文件原先是否缺失。

旧记录没有内容指纹、非 Git 项目、脏起始内容无法从 Git 恢复、快照不完整、
超出指纹预算时保留审阅能力并拒绝不安全的撤销。
指纹采用 64 KiB 流式缓冲，单文件最多 8 MiB、每次快照最多读取 64 MiB，
仅在轮次开始和结束采集，不随产出列表轮询重复哈希整个目录。
此检查不提供操作系统级文件锁，外部应用仍可能并发写入。
