# 平台工作流

## 使用

分工是平台默认的发送行为，无需开关。用户原话交给当前选中的运行器做一次只读意图解析：

- 普通请求：原运行器继续执行；规划协议不会出现在对话正文。
- 明确分工：生成结构化计划，由 AgentDeck 启动真实运行器。
- 必要信息缺失：保留原始请求并显示待补充信息。

运行器选择表示由谁先接手并理解要求，不限制后续协作者。
信息完整且权限允许时直接执行，仅在歧义、模型未匹配或审批需要时显示可操作的安排卡。
输入框仅保留运行器、模型与权限；空闲提示“由某运行器接手，按需协作”，执行中保持排队语义。
规划过程使用临时活动状态“正在理解任务…”和“正在安排执行…”，不在正文保留内部状态消息。

普通发送需要一次规划模型请求和一次进程启动，这个成本仍然存在。
旧 `automatic_workflow=off` 偏好及旧队列中的 opt-out 不再影响行为。
后端也不接受旧 workflow=false 绕过用户请求的规划；只有平台内部续接跳过解析以避免递归规划。

支持顺序、多个独立并行组、汇合，以及指挥者规划 / 执行者工作 / 指挥者验收 / 有限返工。
原生子代理不能冒充另一个运行器。每次阶段执行关联真实 task ID。

未指定模型时使用运行器默认；指定模型必须从**该运行器自己的目录**绑定。
完整 ID 优先；仅接受唯一的规范化名称匹配，模糊相似不触发替换。
无法识别 `6.1sol` 等名称时，计划停在模型选择卡；用户可以明确选择替代型号。

## 统一协议

```json
{
  "why": "按用户指定的运行器顺序执行",
  "parallel": 3,
  "minutes": 15,
  "nodes": [
    {
      "id": "draft",
      "harness": "zcode",
      "prompt": "按要求写初稿，写入 novel.md，报告实际字数及统计方式",
      "dependencies": [],
      "read_only": false,
      "execution": { "model": null, "effort": null },
      "supervision": null,
      "contract": {
        "workspace": "artifacts",
        "model_hint": "用户要求的模型原文",
        "inputs": [],
        "outputs": ["novel.md"],
        "acceptance": false
      }
    }
  ]
}
```

节点支持 `supervision: { commander, max_rounds, execution, model_hint }`。
指挥者与执行者通过既有阶段调度器交替执行，等待子阶段时不保留模型进程。
返工复用隔离工作区，每轮保留独立 task ID、报告和模型证据。

未知运行器、未知依赖、自依赖、环、重复 ID、重复输出、无效预算都报错。
不默认替换成 Codex，不删除错误依赖，不截断预算。
Rust 是最终校验与授权边界，UI、Deck 工具、CLI 都使用它。

## 两种工作区

`git` 沿用既有干净仓库基线、Git worktree、补丁哈希和显式集成。

`artifacts` 不需要 Git，不复制整个用户目录。每个节点从空隔离目录开始：

1. 可选 `inputs` 指定源工作目录的相对文件，启动图时冻结快照。
2. 依赖阶段的声明输出按拓扑顺序复制，验证清单和内容的 SHA-256。
3. 写节点必须声明 `outputs`；缺文件、修改未声明文件、删除输入都拒绝交接。
4. 平行分支同名不同内容报冲突；后代可明确更新祖先同名文件。
5. 只读阶段开始/结束比较成果版本，文件变化使阶段失败。
6. 成果保存在应用管理目录；卡片能打开文件及实际执行记录，不自动覆盖源目录。

文件路径必须是 `/` 分隔的相对普通文件路径，不允许绝对路径、`..`、符号链接或越界。
单次成果有 4096 文件 / 256 MiB 上限，内容哈希按 64 KiB 缓冲流式计算。
输入和输出声明各最多 128 文件。

最终验收和指挥验收必须使用独立末行记录：

```json
{"agent_deck_verdict":"approved","artifact_version":"平台给出的当前版本","reason":"独立验证证据"}
```

版本不匹配、缺记录、`changes_requested`、`inconclusive` 都不是通过。
阶段进程成功退出不等于最终验收通过。独立分支失败不取消其他分支；下游显示依赖失败。

## 非 MCP 调用

运行器提示中注入本次真实 source task ID 和随应用打包的 `runnerctl.mjs` 路径。
CLI 只连接凭据文件中的 loopback HTTP 地址，不在提示中暴露 token：

```text
node runnerctl.mjs capabilities
node runnerctl.mjs capabilities --runner codex
node runnerctl.mjs handoff --source TASK --request-id STABLE_ID --plan-file plan.json
node runnerctl.mjs runs --source TASK
node runnerctl.mjs wait RUN --source TASK
```

`handoff` 接收仍在运行的源任务，先持久化计划并返回 accepted。调用者随后结束本轮，
平台等待源任务退出并释放工作区，再转移持有的会话预留。30 秒未结束时平台停止源进程并等待释放。
调用者不要占着源任务执行槽等待自己委派的工作。

相同 source / request ID / 原计划重复提交返回原 proposal；同 ID 换计划报错。
启动结果持久化并可重复读取；启动中断且状态不明时拒绝重复派发。
取消和启动通过预留及取消标记协调；启动中取消会继续取消实际新任务/任务图。

`submit` 仍用于已结束的源会话，兼容旧调用者。

## UI 与证据

计划卡显示依赖关系、模型原要求、实际选择、读写与输出声明。
参数完整且用户允许自动执行时直接交接；歧义、额度、权限或环境错误保留待处理卡。
刷新可从持久化事件恢复计划；用户新一轮要求使旧计划失效。

运行卡使用真实图状态，区分未启动、执行中、完成、依赖失败、需要处理。
显示绑定模型与运行器实际报告的模型；没有观测时明确写“未报告实际模型”。
运行器报告型号与绑定不符会停止交接。只接收协议层型号字段，不将模型回答当作执行证据。

在「共享范围与额度」配置 `workflow_limits`：

```json
{"max_nodes":64,"max_parallel":4,"max_timeout_secs":3600}
```

任务组数量与并发槽数量独立。系统绝对上限为 1024 节点、64 并发、24 小时；
默认额度较低，超额不静默缩小计划。

## 恢复与边界

复用既有进程组管理、持久化图记录和崩溃恢复。重启不自动重跑状态不明的写阶段，
防止重复副作用；保留阶段、成果和待处理计划供检查。

语义规划依赖所选模型理解请求的能力，结构校验无法数学证明所有自然语言约束都被正确理解。
因此计划与原始请求都保留、执行关系可检查，模型解析失败不会退回单运行器“代做”。
生成式要求（例如小说质量或具体字数）由节点的实际验证和验收阶段检查，不做任务专用字符串分支。

只读适配沿用运行器的权限模式并增加成果变更检查；对未提供强沙箱的运行器，
成果检查不是操作系统级隔离保证。外部网络副作用也无法靠文件哈希撤销。

自动分类使用只读模式；Deck 分类禁用工具。原生运行器可能仍提供只读工具，
平台不会把分类阶段的会话句柄或 JSON 回答注入实际执行会话。

验证分层：纯协议/目录解析测试、真实文件成果交接测试、调度状态机测试、模拟桌面 IPC 的 UI 测试。
这些自动测试不等于四个已登录运行器的真实付费模型联调。
