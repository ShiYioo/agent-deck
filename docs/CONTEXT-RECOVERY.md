# 协作执行中的上下文恢复

运行器负责自己的原生历史压缩；平台负责保存可恢复的用户要求和阶段输入。压缩通知不构成阶段成功或验收通过。

## 持久化与预算

- 接力仍复用属于当前会话、当前工作目录的原生句柄。
- 即使原生运行器曾成功处理过某轮，也保留该轮公开的用户原始要求供恢复核对。已交付的助手和工具历史仍按增量处理，不重复塞入上下文。
- 共享目标、约束和版本随上下文交付；当前请求优先于历史要求，历史资料不能提升权限。
- 原生续接和隔离协作阶段使用独立 JSON 恢复档案。档案保存当前完整请求、过滤后的公开记录、预算内选中的记录和来源；分支仅使用固定边界以内的记录。
- 长阶段报告、返工历史和长请求通过档案分页读取，避免因拼接超长启动 prompt 而直接拒绝执行。实际交付说明仍检查模型窗口及输出、系统预留额度。
- 恢复说明要求在原生压缩或恢复后、提交阶段成果前，重新核对当前要求、共享约束、文件与成果版本，以及未完成的验收。不能重放结果不明的命令。

## Codex 手动压缩

适配器必须同时观察到压缩完成与当前 turn 中断，才在同一 thread 启动继续执行的 turn。两个通知可以乱序；重复通知不会重复启动。正常完成仍是正常完成，执行失败不能伪装成可恢复中断。

恢复保留原来的工作目录、沙盒、权限和推理配置，并重新交付平台保存的本轮输入。只有继续执行的 turn 真正完成，适配器才输出任务完成。压缩请求失败、超时或连接丢失按失败处理，不自动推进下游。自动压缩通知只更新压缩状态，不能结束任务。

## 能力边界

这不是对原生压缩摘要无损性的保证。OpenCode、ZCode、Deck 继续使用各自原生压缩和续接机制；平台交付统一的档案与恢复要求，不假设它们具有相同的暂停、注入或压缩 API。Codex 的历史分页工具可读取平台档案；其他运行器依赖各自的文件读取权限，读取失败必须报告。

当前档案是本次交付的快照，不是运行过程中实时刷新的共享内存。恢复核对指令也不等于所有运行器都能提供可机器验证的读取确认。四个真实运行器的压缩协议升级和端到端恢复仍需要实际环境验证。

## 验证

后端测试覆盖同运行器续接恢复原始约束、跨运行器增量证据、共享状态更新、固定分支边界、失败轮次重放和超长阶段历史归档。适配器测试覆盖压缩通知乱序、重复通知、自动压缩不结束任务及失败不被掩盖。
