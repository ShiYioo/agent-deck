# 运行与对话契约

## 职责

- `agent/deck-agent.mjs`：模型配置归一化、SDK 会话恢复、项目内工具、审批与中断、模型降级。任务请求与审批指令可并发处理，但不会同时执行两个任务请求。
- `src-tauri/src/pi_session.rs`：sidecar 的 stdin/stdout/stderr 生命周期，事件持久化和分发，结果落库，进程异常与取消超时兜底。
- `src-tauri/src/runner.rs`：原生 CLI 的进程组管理与事件解析。主动取消与异常退出分开记录；协议报告失败时不能因进程退出码为 0 而显示成功。
- `src-tauri/src/conversation.rs`：公开上下文编译、目标 harness 原生句柄选择、增量接力及长记录快照。不依赖独立总结模型。
- `src-tauri/src/coordination.rs`：原生绑定与交付状态、版本化共享任务、原文分页查询、工作目录租约、重启恢复阻止及单实例数据目录锁。
- `src/types.ts`：SDK 事件和统一事件的适配器。实时与历史回放共用，保留部分回复与错误，分类鉴权和额度问题。
- `src/taskState.ts`：任务更新的纯函数归约。流式事件是完整快照，只替换正在流式输出的同一条消息，不追加重复回复。
- `src/App.tsx`：派发、选择、排队及操作协调。启动前等待监听就绪，提前到达的事件暂存，任务注册后回放；同步镜像保证结束事件可以读到刚到达的会话句柄。

## 生命周期

任务从 `running` 进入且只进入一种终态：`done`、`failed`、`cancelled`。

`deck_run_end` 携带 `ok` 和 `status`。结果以该协议终态为准，不以 sidecar 自身的退出码代替。初始化错误、提前 EOF、异常退出也必须写入事件并发出 `task-exit`，不能只写 stderr。

主动中断先尝试 SDK 协作取消。待审批工具会立即解除等待；后端等待最多 5 秒，仍未收尾则终止进程。原生 CLI 取消使用进程组；sidecar 委派的 CLI 支持取消信号并在 Windows 终止进程树。

stdin EOF 等待当前 SDK 请求完成，避免压缩请求尚未返回就退出。进程关闭使用实际支持的 `close` 指令，不使用未定义的 `__CLOSE__`。

## 对话与权限

续聊句柄是 `deck_session_file.path`，不是展示用的会话 UUID。恢复文件不存在时明确报错，不悄悄新建空会话。原生 CLI 续聊复用原工作目录，不再次创建隔离 worktree。

输入的用户消息独立持久化，不依赖模型返回，也不被接力传输 prompt 替换。每轮仍是独立任务记录，但侧栏按 `conversation_id` 聚合为一个聊天。历史回放包含截至所选轮次的所有 harness 公开事件，消息带来源；旧数据未升级时仍按 harness 与原生 session 分组。

续聊、`@harness` 路由及接力按钮均沿用逻辑会话。首次切换同步已持久化的公开记录；A → B → A 恢复 A 自己的原生句柄，仅补 A 上次成功轮次之后的记录。失败或取消时不假设输入已被消费，保守回放历史证据。自动接力请求隐藏，真正用户输入保持可见。旧会话升级按既有 harness/session 归属回填，不按目录猜测。

当前接力沿用 CLI/sidecar 适配，将历史作为带来源的资料传入，不伪造原生工具调用或移植私有推理。超过 3000 字节的上下文载荷写入应用数据目录 `conversation-context/` 的 JSON 快照，提示执行者读取完整本轮要求及按需读取记录；该阈值是 CLI 传输策略，不是模型 token 预算。若权限阻止文件读取，必须报告并等待，不能宣称已获得历史。快照包含用户/工具原文，尚未增加跨供应商脱敏或授权层。

失败派发前创建的快照自动清理；已派发快照随所属聊天记录删除，清理失败会提示。此操作不删除 harness 自有原生缓存。`runtime_bindings` 保存各 harness 的句柄、最近任务及成功游标；`context_deliveries` 保存交付范围和本轮执行结果，`done` 不表示模型已经理解或接受全部历史。

`conversation_seq` 在归属落库时分配，防止同毫秒创建的轮次或时钟变化打乱接力顺序；旧数据按已有时间和 ID 确定性回填，无法恢复旧记录从未保存的真实先后关系。会话读取使用归属/原生句柄索引，不再扫描全部任务正文。原文搜索是会话内的字面子串查询与分页，不是向量检索或 FTS 索引。

`conversation_state` 保存用户维护的目标、约束与决策，按版本比较后更新，拒绝过期写入。每次上下文同步包含当前状态，但本轮用户要求仍优先。执行详情中的“共享任务”可编辑状态，“上下文记录”可查看绑定、交付结果及搜索原文。原生句柄损坏时可确认“重建上下文”：只清除该会话目标 harness 的句柄，下次回放公开记录，不删除聊天原文或原生缓存。

应用通过独立 SQLite 文件的独占事务持有数据目录单实例锁，避免另一个 AgentDeck 实例同时控制该数据库。规范化工作目录租约覆盖整个普通运行或指导协作，包括阶段空隙；另一聊天在同目录启动也被拒绝。删除和启动共享会话变更保留，避免在派发中删掉根记录。不是对任意外部 CLI、编辑器或其他数据目录的全局文件锁。

重启时将遗留 `running` 任务标为失败、记录中断事件，将未完成交付标为 `interrupted`，运行中的协作改为 `needs_attention`。遗留目录保持恢复阻止；用户必须确认旧执行者结束且核对工作区，才可重新派发，不自动重跑命令。CLI 与 sidecar 均启用进程组整树退出保护；Windows 使用库提供的关闭 Job 时终止子树机制。对旧版本或 Unix 异常退出不假设无遗留进程，恢复确认仍保留。

删除运行中的聊天先停止相关协作与任务，等待最多 10 秒确认终态，再删除任务及绑定/交付/状态元数据；超时保留记录并报错。异常重启尚未确认恢复的聊天也拒绝删除，避免绕过目录恢复阻止。迟到的事件不能重新创建已删除任务的日志。启动失败的落库任务也会收尾为失败，不留下永久 `running` 状态。CLI 即使已经关闭输出流，等待退出期间仍会响应取消；执行者退出后终止剩余子树，后台子进程不能越过目录租约继续运行。

跨 harness 权限不能直接互认：受限沙箱、审批及只读模式保守映射为目标只读模式，只有原本不受限的模式保留完整权限；用户可随后显式调整。接力不自动新建 worktree，也不在旧执行者仍运行时另起执行者。运行时自己的自动 compaction 仍可能发生，与独立接力总结无关。

排队续发保留原模型、权限、目录和项目，以及其余队列项。续发启动失败时保留队列并回显错误，不静默丢弃。

审批以 `taskId + toolCallId` 定位。批准/拒绝不会移除运行注册表；只有收尾时移除。切换聊天不能把后台任务的审批发给当前任务。审批传输失败保留操作区供重试。

不在编码会话完成后自动追加记忆抽取请求，以免改写待恢复的上下文、执行额外工具或把内部请求显示成用户对话。已有项目记忆仍可注入；会话压缩明确禁用工具。

## 反馈与验证

指导协作由 Rust 后端顺序编排：指导方只读计划、执行方修改并测试、指导方只读验收；
未通过时把具体反馈交还执行方，最多三轮。协作状态与阶段任务 ID 写入 SQLite，
桌面事件持续更新状态；每个阶段复用源任务目录、项目及逻辑会话，避免切换 harness 时落入不同 worktree 或拆分聊天。
最终验收只接受回复最后一行的独立 JSON verdict，引用示例或普通文本不能误判通过。
协作不递归委派，并要求源任务先结束，同一规范化工作目录不可并行启动第二个指导流程或手动任务。受限源模式或当前只读选择让实施阶段也只读，不静默扩大权限。每阶段时限可设为 1 到 60 分钟，默认 15 分钟，最多 3 个实施轮次；超时取消并等待收尾，不自动无限返工。指导目标取会话最新的公开用户要求，历史由统一上下文编译器同步，不另行截断或调用总结模型。

`check_harness` 检查本机可执行文件、sidecar 文件和启用的模型配置。它不访问上游，不代表 API Key 或账户额度已经通过在线验证。浏览器预览明确显示 IPC 未连接。

`pnpm test:runtime` 启动真实 sidecar 并连接本地 HTTP 模拟模型服务，验证配置地址、流式消息、会话恢复、工具目录、重复审批、中断、上游错误和 EOF。它不使用真实密钥、不消费实际模型额度。

`pnpm test:ui` 验证 IPC 竞态、流式快照、错误回显、历史回放、跨任务审批、队列配置与草稿保留，并覆盖桌面及窄屏布局。`tests/relay.spec.ts` 覆盖 A → B → A、权限保持、竞争执行者拒绝、共享删除、无句柄接力及接力按钮。`tests/context.spec.ts` 覆盖版本冲突时保留草稿、恢复确认、句柄重建、原文分页及窄屏操作。此层 IPC 为模拟桥，不能替代真实供应商与桌面端的联调。

`cargo test` 验证 CLI 适配器、运行指令注册表、退出状态、历史持久化及 worktree 行为，也验证上下文增量范围、原文快照、快照清理、旧会话迁移、启动互斥、目录租约、独占实例锁、重启恢复、交付结果、共享状态冲突和确定性轮次顺序。Windows 还启动真实测试进程，验证释放进程组会终止后代进程。

当前交付不包含 App Server/ACP 原生历史导入、并行写入调度、自动 patch 集成、远程 A2A、自动脱敏或自适应递归。这些探索不能绕过当前目录租约，也不能用提示词冒充已验证的权限隔离。
