# 性能约定与验证

性能优化保留原始事件、任务顺序、恢复规则与文件产出隔离；不通过截断历史或省略最终扫描换取速度。

## 高频更新

- `applyTaskUpdates` 按来源任务、消息类型与 streamId 索引快照，避免每个快照遍历历史。
  索引以不可变事件数组作为 WeakMap 键；分支添加新流时复制索引，历史数组释放后可回收。
- 仅元数据的状态更新不复制事件数组；无变化或已完成消息收到迟到的流式快照时复用原对象。
- 恢复时的历史与缓冲区重叠匹配使用线性前缀算法，避免重复事件造成平方级回扫。
- 每个对话时间线持有一个语义行投影器。未改变的行复用引用，供 React memo 跳过历史 Markdown 渲染。
  工具结果、思考状态、来源、统计变化仍会产生新行；缓存只保留当前投影。
- 时间线的消息元素与工具分组分别缓存，产出刷新不重建全部消息元素。
- 语义归约仍遍历输入事件，事件数组在实际修改时仍需浅复制；当前优化不等同于完整历史虚拟化。

## 启动和文件扫描

- 桌面历史列表使用 `list_task_summaries`：在 SQL 查询中排除 baseline 与 result_manifest，
  避免为侧栏读取、分配和传输目录快照。完整记录仍由 `get_task` 和内部任务逻辑读取。
- 历史列表查询、轮次目录扫描与 Git 子进程在阻塞工作线程运行，不占用桌面主线程。
- 运行中产出扫描完成后再安排下一次扫描；隐藏窗口间隔为 15 秒，可见时为 4 秒。
  同任务的最终或手动扫描等待在途请求后重新读取，保证最终快照不会被旧扫描替代。
- 旧版非 Git 任务的产出扫描在 5000 个条目处结束整个遍历。

## 验证

- `pnpm bench:ui`：在同一进程内构造 10000 条历史消息，测量 100 批、每批 64 个快照的状态更新，
  同时统计未变化历史行的引用复用数。此为局部微基准，不是整机性能或真实任务耗时。
- 本次本机测量：状态更新约 464ms → 3.3ms；历史语义行复用 0/10000 → 10000/10000。
  时间会随硬件、JIT 和后台负载变化，不作为 CI 的固定时间门槛。
- `tests/performance.spec.ts` 验证历史读取次数上界、来源隔离、终态保护、不可变分支、
  工具配对、纯归约及慢扫描后的最终快照。
- Rust 测试验证轻量列表不携带大快照，且完整任务数据保持不变。
- 提交前运行 `pnpm test:ui`、`pnpm build` 与 `cargo test --lib`。
