# AgentDeck 设计系统

> 实现入口：`src/styles.css`（全部令牌与关键帧都在这里，组件只消费类名）。

## 设计立场

整体布局和交互习惯以 Codex 桌面工作台为参考。重点是项目、聊天、执行结果，
不是为 AgentDeck 另造一套装饰性视觉身份。主区白色、单侧栏中性灰、控件紧凑，
按工作流组织信息。不要重新加入双侧栏、点阵背景、浮动品牌符或彩色发送按钮。

## 布局与交互

- 单侧栏承载新聊天、搜索、项目分组、设置。项目按规范化路径聚合，不能因任务排序重复分组。
- 项目可折叠，项目旁的新聊天按钮沿用对应目录。已创建但尚无任务的项目也必须可见。
- 新聊天标题和输入区居中；已有会话正文独立滚动，输入区固定在底部。二者共用 Composer。
- 窄窗口默认收起侧栏，展开时使用遮罩；选择聊天后关闭抽屉。不能挤压正文宽度。
- 消息使用正文比例字体和 Markdown。等宽字体只用于代码、路径及工具详情。
- 用户消息靠右，助手正文不加框。思考、工具调用及输出默认折叠，失败结果展开。
- Diff、停止、审批保留明确入口；会话接力属于次级操作，默认收起。
- Enter 发送、Shift+Enter 换行，输入法组合期间禁止发送。发送失败保留输入，切换聊天保留各自草稿。
- 运行期间有输入时发送入队，没有输入时发送按钮变为停止。不能放置未实现的附件入口。
- 菜单支持 Escape、外部点击关闭、键盘选择，并按视口定位，不能越过窗口边缘。
- 设置使用分区导航和行式表单，页面分区不包装成卡片。焦点状态及开关名称必须可访问。

## 色彩

| 令牌 | 值 | 用途 |
|---|---|---|
| `--bg` | `#ffffff` | 主工作区 |
| `--bg-subtle` | `#f5f5f5` | 侧栏 |
| `--border` / `--border-strong` | 黑色透明度 | 轻量边界 |
| `--text-1/2/3` | `#242424 / #666666 / #8c8c8c` | 三级文字 |
| `--harness-zcode` | `#059669` 翠绿 | ZCode · GLM 的身份色 |
| `--harness-codex` | `#0284c7` 天蓝 | Codex · GPT 的身份色 |

**身份色纪律**：绿/蓝只允许出现在「harness 是谁」的语义上
（智能体选择器中的小信号点），绝不用于装饰或主要按钮。
发送键使用黑白，侧栏选中项使用中性灰。失败/审批才使用红色/警告色。
Tailwind stone 令牌也映射为中性灰，避免遗留组件重新引入暖纸色。

## 字体与排版

- 界面：system-ui / Microsoft YaHei 栈；代码：Consolas / monospace。
- 新聊天标题 26px，消息正文 14px，侧栏与控件 12–13px，次级执行信息 12px。
- 字距为 0，不使用负字距、随视口变化的字号或大面积营销标题。
- 面板圆角不超过 8px；图标按钮尺寸固定，文本和长路径截断或换行，不推动布局。

## 动效

三档时长，一条主曲线：

| 令牌 | 时长 | 场景 |
|---|---|---|
| `--dur-1` | 120ms | hover、按钮、颜色过渡 |
| `--dur-2` | 140ms | 菜单、折叠、页面淡入 |
| `--dur-3` | 180ms | 弹窗、侧栏出入场 |
| `--ease-out` | `cubic-bezier(.22,1,.36,1)` | 一切出场的默认曲线 |

清单：

- hover 以背景或边框轻微变化反馈，不抬升工作台控件。
- 新聊天和会话不使用装饰性入场、浮动或流光动画。
- 运行状态允许小尺寸旋转或三点指示，输入框保持可输入。
- 自动滚动仅在用户位于底部时跟随；用户上翻后显示回到底部的图标按钮。

### 动效引擎

- `src/motion/MotionProvider.tsx` 集中管理动效策略，使用 Motion 的 LazyMotion 延迟加载动画功能。
- 菜单、弹窗、侧栏使用 `MotionLayer` 和 `AnimatePresence`，统一短时曲线，可中断，不使用弹性缩放。
- 退场层即时设置 `inert`、`aria-hidden` 和不可点击状态，不能在动画未结束时接收误操作。
- 页面只做淡入；输入区位置变化使用局部 layout projection，不在消息更新时测量整个页面。
- 折叠详情使用 `Disclosure`，仅在展开时挂载内容。项目超过 40 条时不逐帧动画列表高度。
- 除明确的展开/收起外，优先动画 opacity / transform；不动画 box-shadow、背景位置或文本尺寸。
- 不给每条流式事件挂入场动画，不为历史回放排队播放动画。
- `useFrameQueue` 合并同一帧的 IPC 更新；后台使用 64ms 定时兜底，终止事件前立即排空队列。
- `useAutoScroll` 每帧最多提交一次自动滚动，并观察内容/视口尺寸变化；上翻立刻暂停跟随。
- textarea 在绘制前完成尺寸更新，窗口宽度变化时按帧重算；不动画输入高度或打字光标。
- 侧栏和输入区的回调必须稳定，使 memo 不被内联回调抵消。
- 系统减弱动效时 CSS 和 JS 动画一起关闭，滚动直接定位；后台窗口暂停持续指示动画。

## 图标语言

新增操作图标使用 `lucide-react`。现有 `icons.tsx` 可在尚未迁移的组件中继续使用，
智能体品牌资源沿用 `HarnessIcon`，不要为了操作按钮再手绘 SVG。全站不使用 emoji。

- 规格：24 视窗 / 1.8 描边 / 圆角端点 / `currentColor`，尺寸由 `size` 控制；
- 应用图标可保留原资源，主工作区不摆放装饰性品牌插图；
- 语义图标按工具名自动映射（EventLine）：shell→终端、file→文档笔、web→地球、其余→扳手；
- 工具按钮优先使用熟悉的图标，并附上 title 和 aria-label。

## 无障碍

`prefers-reduced-motion: reduce` 时，CSS 动画和过渡关闭，Motion 时长为 0。
偏好变化需实时响应，信息结构不变。这是硬性要求，新增动画不得绕过它。

## 新增动效的检查单

1. 有明确的信息职责吗（反馈/引导/连续性）？纯装饰不加。
2. 时长落在三档之内？曲线用 `--ease-out`（需要回弹才用 `--ease-spring`）？
3. 会不会在流式输出时高频重放？进场动画必须只作用于「新挂载的节点」。
4. `prefers-reduced-motion` 下是否安静？

## 验证

运行 `pnpm build` 和 `pnpm test:ui`。UI 测试使用模拟桌面接口，不派发真实 agent。
桌面和窄屏截图位于 `test-results/`，检查菜单边界、长名称、正文宽度与输入区。
